# BaattleCraft 原型經驗與開發建議

這份紀錄彙整兩次以 v2 為起點的獨立嘗試，以及主線 v1–v5 和較早的 3D Garden 研究。BaattleCraft 的玩法優先依使用者已確認的方向與已解析的 BattleCraft 地圖證據。v5 提供目前可玩行為與回歸測試的起點。

## 原作依據與 Web 規則

| 項目 | 目前依據與接續方式 |
| --- | --- |
| 場外購兵 | 使用者確認角色留在場外信標時，金幣補足應自動購買，停留期間可再買。SC1 SPEED 基準樣本 `2tzpVkp9` 的 Trigger #9 以己方角色位置與資源門檻為條件，扣款並整批生成，保留 Trigger 供後續掃描。v5 的 0.5 秒最短間隔屬 Web 試作設定。 |
| 四端路線 | 樣本 Trigger #10–17 支持優先攻向對側，對側失守後以另一敵方核心為目標。四端交會後延續原軸是設計基準，改派時的具體路徑可先原型驗證。 |
| 隊伍與視野 | 使用者方向是四人小房間 2v2，隊友可從指揮官走向哪個信標判斷購兵意圖，敵隊受戰爭迷霧限制。席位配置、購兵資訊的可見範圍與連線架構仍待驗證。 |
| 經濟與終局 | SPEED 樣本之間的收入與資源 Trigger 有差異。樣本 #2 以敵方勝利所需 Pylon 的存亡為判定，#3 檢查自己的 Pylon。單席失守後的收入、既有部隊及雙方最後核心同一步歸零的 Web 處理仍待定。 |

原論壇 `BattleCraft-Fastblack-SPEED.rar` 尚未取得。SC1 鏡像的 Trigger 可支持上述樣本結論，論壇附件的身分和實際收入速率仍有待驗證。SC2 Hyper 的資源節奏及單位時間倍率屬另一版本。原作名稱為 `BattleCraft`，Web 顯示名稱為 `BaattleCraft`，儲存庫為 `battle_craft`。來源與版本詳見[原作研究](battle_craft-research.md)及[樣本雜湊](battle_craft-scx-checksums.csv)。

## 早期主線與 3D Garden 試作

- v1 以按鍵買兵，v2 把信標移到場外，站著等收入可成交一次。最初 v3 快照只在踏入時判定，目前入庫 v3 沿用 v2 的等待一次。v4 為傾斜科幻 3D 試作，v5 提高俯角並確立持續購兵，另保留血條、帶對局時間的最新訊息及分色事件紀錄。原型數值可用於重播舊版。[版本紀錄](../README.md#版本紀錄) · [v5 說明](../v5/README.md)
- 用實際鏡頭選模型，優先辨認四端核心、兩條戰線、中央兵群、敵我隊色與場外信標。以原創半寫實工業科幻為美術方向。從一段道路、一座核心與一種兵團試起，保留程序幾何回退；外部裝飾和貼圖由渲染層處理。模型載入失敗可逐件回退，切換或捨棄過期物件時要釋放幾何、材質與貼圖。[3D Garden 歷史交接](battle_craft-source-3dgarden-handoff.md) · [現行開發交接](DEVELOPMENT.md)
- 布偶救援隊的素材試作曾發現，把被替換的實例縮成零仍會提交頂點。BaattleCraft 應自行量測同一鏡頭、解析度和兵量下的模擬及渲染成本，再選擇空間分桶、實例化或減少透明特效。記錄裝置、瀏覽器、冷啟動、P95 幀時間、draw calls、三角面及可取得的貼圖用量。低多邊形只保留為歷史建議中的效能對照，正式視覺維持半寫實方向。[效能經驗](DEVELOPMENT.md#可移植的-3d-garden-試作經驗)

## V2 分支一：四端模擬與驗收

這次分支以西側玩家、北側電腦盟友、東南兩側敵軍驗證四席個別錢包與核心。交接記載 Node 邏輯測試涵蓋四席出兵、扣款、缺錢等待、暫停、核心改派和同一步雙方最後核心歸零。另有工業科幻、低多邊形與 Canvas 備援草稿，瀏覽器操作、手機效能與大量兵團尚未實測。分支當時未比對 v5 原始碼。公開對話（連結保留於本機）

- 讓點地、觸控或編制按鈕只設定行走目標。由模擬在角色抵達後按固定順序處理移動、收入、信標資格、扣款與整隊生成。驗收應核對累計購買和生成事件，避免把已戰死的士兵算成未出兵。分支的「本次停留已成交」只適用舊 v2 預期。v5 測試要在同一次停留看到第二筆有效購買。
- 分開記錄出兵席、隊伍、目前目標。核對從哪一席扣款、部隊從何處出發、同隊交會及核心陷落後改派。分支的回中央改道、單席失守停收停兵、既有部隊繼續作戰和同一步平手，可用來提出測試情境與討論規則。
- 先收集同一步的攻擊，再一起套用傷害與判定終局。將單位遍歷順序倒轉，核對同一輸入的結果。暫停或切換畫質前後比較模擬步、錢包、核心 HP、士兵 ID 與位置、目標及勝負。

## V2 分支二：開發總覽與重播基準

這次交付為開發總覽和建議。總覽記載以 Node 執行 v1、v2 原始 HTML 內的 JavaScript，測過點地、按鍵、暫停、恢復、失焦、重開與終局。v2 案例在第 150 步補足 5 金後成交，停在原地到第 330 步仍只成交一次。兩版的無購兵案例都在第 682 步敗北，原型也測過同一步雙方核心歸零。這些步數、價格和終局是舊版的回歸資料。開發總覽（連結保留於本機） · 公開對話（連結保留於本機）

- 先記下 v5 入口、commit、規則版本、模擬步、輸入及必要的隨機種子。若已有可重播案例就沿用，核對扣款、生成、傷害與終局。每輪選一個有量測或試玩依據的改進，保存同條件的前後證據與回退方式。
- v2 的單軸攻擊距離只適用於當時的橫向戰線。四端原型要測 x 近但實際相隔很遠的敵兵不會互打，且中央交會時能接敵。3D 攝影機下要驗證點擊投影回戰場座標的位置與角色實際抵達的信標一致。
- 單機失焦暫停是本地行為。若日後加入房間，另測背景分頁、同時購兵、事件重送、掉線重連及四個獨立客戶端結算。桌機和手機也要分別測觸控、斷網以本機 HTML 開一局、關閉 WebGL 的備援及模型載入失敗。

## 接續驗收順序

1. 先固定 v5 的購兵基準。現有 Node 測試已覆蓋 5 金與 12 金信標的站等和重複付款。下一組完整輸入驗收可用現行兵價測到達前不扣款、差 1 金時原地補足成交、同次停留有錢再買第二隊、離開後停止，以及多次下達移動意圖時每筆成交只扣款及生成一次。[現有購兵測試](../v5/qa-exact-functions.cjs)
2. 為四端原型測席位與隊伍歸屬、對側優先、核心失守後改派、中央交戰及確定的終局規則。v5 單機程式已處理雙座核心同時歸零的平手，四席的隊伍級平手仍待確認。把暫定選項寫入案例條件，並保留對應的 SCX 樣本和 Trigger 編號。[v5 程式](../v5/game.js) · [四人原型議題](https://github.com/xdxd-lab/battle_craft/issues/1)
3. 以同一筆輸入比較呈現設定前後的核心狀態。連線架構選定後，沿用同一份事件紀錄驗證兩台到四台裝置的狀態一致性，另以各隊視角驗收購兵意圖和敵方迷霧。[一致判定與重播](https://github.com/xdxd-lab/battle_craft/issues/2) · [隊友資訊與迷霧](https://github.com/xdxd-lab/battle_craft/issues/3)
