# BaattleCraft 開發交接

## 起點：v5-9 封存，v6-0 接續

在戰區外的隊伍補給區選購部隊。玩家站在信標上時，金幣足夠就自動購買，錢不足就繼續等。只要還站在上面，下次存夠會再買，兩次購買至少間隔 0.5 秒。單機保留 v5，四席則以 v5-9 與內部重播格式 7 當回歸基準；新開發從 v6-0 起。

十字戰場的兩條軸線服務 2v2。部隊走到路口時通常沿原軸線向對側前進。隊友能從指揮官走向信標預判購兵意圖；敵人應受戰爭迷霧限制。四席試作已有飛行兵種；空域與原作一致性尚待正式驗收。金幣、扣款、出兵、碰撞、傷害與勝負需一致判定；裝飾性粒子與碎片可本地呈現。

v5 保留血條，最新訊息和事件紀錄帶對局時間。顏色區分我方、敵方與系統，並標記事件嚴重程度。正式版本再評估放入設定，切換血條和工程師紀錄。

用語：Protoss 中文統一使用「神民」，英文 Protoss 保留。引用外部原文、Trigger／CHK 字串、第三方授權與歷史快照時照原文保留，不追改。刺蛇（Hydralisk）、破壞能（Archon）、死靈戰機（Wraith）已在四席試作實作。

## 可移植的 3D Garden 試作經驗

- 用遊戲實際鏡頭挑模型。布偶救援隊由俯角看細路燈時輪廓不清楚，紙板樹需要朝向鏡頭。兩款寫實燈具在暖色玩具場景不合適，在 BaattleCraft v4／v5 則用作星際場景的配角。
- 用來源、GLB 大小、材質貼圖、三角形與繪製呼叫分別記錄。布偶救援隊測到把原 instance 縮成 0 仍會提交頂點，木桶替換後單張圖約多送 3.1 萬三角形；這是另一個專案的 Chrome 結果。BaattleCraft 的實機幀時間、GPU 記憶體與行動網路載入仍需量測。
- 模型載入失敗時保留原物件或程序模型。切換場景或丟棄過期載入結果時，清理幾何、材質和貼圖；單一模型失敗應可各自回退。
- [歷史版本與素材調查](battle_craft-research.md) 有來源及篩選理由。SC1、SC2 和 Web 試作的購兵條件與數值各自保留來源。3D 戰場優先維持半寫實／寫實材質與清楚的兵種輪廓，並保留辨識敵我、路線和信標所需的對比。

## 重要開發知識來源

- [SC2Mapster Wiki](https://sc2mapster.wiki.gg/) 是 StarCraft II 地圖編輯的社群知識庫。從 [Triggers](https://sc2mapster.wiki.gg/wiki/Triggers) 查事件、條件、動作與 Galaxy 腳本，從 [Data Editor](https://sc2mapster.wiki.gg/wiki/Data) 查單位、武器、效果與行為的資料結構。
- 研究 SC2 版 BattleCraft 時，先用 Wiki 釐清編輯器概念，再回查對應版本的原地圖或作者改版紀錄。SC1 原版的數值、覆寫與判定優先回查 SCX／CHK 和該引擎的行為證據。


## 可長期重複的接手流程

- 每輪先核對當前基準提交、`research/STATUS.md`、相關原始碼與已有的專題研究。早期交接置於 `research/archive/`，不回寫成現在的事實；新發現回填對應的現行頁面，並從 STATUS 串接。
- 開發以原作玩家地圖的節奏和行為為參考，兵種、規則與美術分批校驗。主負責人與獨立設計覆核者先各自解讀證據，再合併或記下歧義；這個專案的深度設計覆核優先用 GPT-6.2 Astra Ultra（可用時）。先做最小可測切片，保持 v5-9 重播。第一個 v6-0 候選切片與待驗項目見 [原始數值／斥候命中](BC-V6-COMBAT-REFERENCE.md)。
- 來源記錄要能接續：找到或採用的素材、首個使用版本、URL／版本與雜湊、授權、衍生處理、驗證結果；分別放入素材目錄對應的 [3D Garden](../assets/3dgarden/README.md)、[Poly Haven](../assets/polyhaven/README.md)、[音樂](../assets/music/README.md)，原作地圖則回填[歷史研究](battle_craft-research.md)。下載原件、完整匯出、無重分發權限資產與私人記錄留在忽略目錄，不當遊戲依賴。
- 交接的未確認項要標明「本機可能未同步」「確知暫定」「證據互相不符」，不要歸類成同一種缺陷。定稿後補上取代前判斷的依據、測項與受影響版本；不要覆寫舊快照。

1. **先讀再寫。** 先核對舊筆記引用的版本、提交、原始碼或實測；分清楚它當時的目的與限制。若新證據推翻舊判斷，另加具日期的勘誤或從新紀錄連回舊紀錄，寫明何以改判。不是把舊原型用今天的名稱一概重標。
2. **新筆記有可追溯欄位。** 記錄日期與時區（預設台北，含時刻時用 `YYYY-MM-DDTHH:mm:ss+08:00`；只知日期就不補造時刻）、適用玩家版號、模擬／重播格式、基準提交、證據與狀態（已驗證／暫定／待核對／已取代）。事件日期與補註日期不同，就分欄；原作地圖、引擎、SC2 模組的版本或雜湊另欄，不能寫成 BaattleCraft 版號。
3. **舊筆記只在需要時補。** 遇到舊版號歧義、後續仍依賴的規則或失效的假設，從 Git 歷史或原始證據補日期／版本。找不到就寫「待核對」，不只憑檔案最後修改時間推論決策日期。已封存的原文及雜湊保留，在[封存索引](archive/local-workspace-20261128/README.md#版本旁註不改原件)補上對照。

建議格式：`日期（時區）｜本作版本／模擬格式｜基準提交｜來源版本或雜湊｜狀態｜決定、理由與驗證`。純文件補註不升玩家版號或重播格式。
