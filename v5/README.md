# BaattleCraft v5｜十字對衝 試作

`battle_craft-v5.html` 是獨立的離線單檔版本；v1～v4 保留。

## 本輪改動

- 攝影機高度由 v4 約 30° 提升至約 49°，俯角增加約 20°，仍保留傾斜透視。
- 信標改為**站在上面就持續自動購兵**：錢不足時等待收入，存夠立刻購買；購買後繼續站著，下一次存夠又會再買。兩次購買至少間隔 0.5 秒，避免大量存款在同一影格全部花完。可步行離開，無須重新進入才能買。
- 兩側基地與每名士兵顯示血條。基地血量會在頂部 HUD 以數字和進度條呈現。
- 最新訊息加入對局時間戳記。下方的 Event Log 以我方、敵方、系統分色，區分資訊、注意、警報等級；記錄購兵、金幣不足、基地受擊、血量門檻與結果。正式版可再放進設定中的工程師模式。
- 因 v4 無操作時約 27 秒便可能敗北，暫時把基地血量 30 調至 60、敵方第一波由 3 秒改為 6 秒、出兵間隔由 6 秒改為 8 秒，讓試玩者有時間理解訊息與補兵。這些是原型數值，尚未定案。

本輪沿用 v4 的 3D Garden 寫實燈具、傾斜 3D 戰場與單機左右軸玩法。四人連線、戰爭迷霧和正式規則待後續討論。

## 購兵驗收（DEV01）

- `node v5/qa-browser.mjs`（`npm run test:browser`）以 headless Chrome 的滑鼠與鍵盤事件操作未修改的 `battle_craft-v5.html`，只讀畫面。需要本機 Chrome，可用 `CHROME`、`ANGLE` 環境變數指定；macOS 預設 Metal，約 25 秒。SwiftShader 軟體渲染過慢，110 秒內未跑完。
- `node v5/qa-exact-functions.cjs`（`npm test`）抽出 `game.js` 的購兵函式，在 VM 內以指定位置與金幣執行。

| 邊界 | 瀏覽器：單步（每格一個模擬步） | 瀏覽器：即時 | VM |
| --- | --- | --- | --- |
| 到達前不扣款、到達 tick 成交 | ✓ | ✓（抽樣） | ✓ |
| 差 1 金等到補足的 tick | ✓ 站著等、抵達時差 1 金、12 金信標 | — | ✓ |
| 停留續購、至少 15 tick | ✓ | — | ✓ |
| 離開後停止、回來恢復 | ✓ | ✓ 停止 | ✓ |
| 連點、重複移動、鍵盤自動重複 | ✓ 與對照組 tick 一致 | ✓ 連點帳目 | — |
| 每筆只扣一次、出兵數相符 | ✓ 逐格帳目 | ✓ 抽樣帳目 | 部分 |
| 暫停不收入、不成交 | ✓ | — | — |
| 離開再進入會重置 15 tick 間隔（現行規則） | — | — | ✓ |

出兵數以畫面單位數核對，只在接戰前（12 秒內）嚴格相等；之後靠事件紀錄與扣款。單步模式攔截網頁的 `requestAnimationFrame`，輸入仍走瀏覽器事件管線。未涵蓋觸控、失焦暫停與其他瀏覽器。本輪未發現 v5 購兵缺陷，未改 `game.js`。
